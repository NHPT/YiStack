# YiStack Coding Standard

> 本文档定义 YiStack 当前阶段的最小编码规范。
>
> 目标不是追求“最完整规范”，而是先收住当前最容易失控的部分。

---

## 1. 通用要求

- 优先遵循现有代码模式
- 优先小范围修改
- 禁止无关重构
- 导出函数、导出类型、关键跨模块函数应带简要中文注释

## 2. 命名

- 名称应直接表达领域语义
- 避免使用模糊名称，例如 `data2`、`tempHandler`
- 状态值、事件名、接口字段名必须前后端统一

## 3. 错误处理

- 错误返回必须尽量结构化
- 不允许吞错
- 不允许只记录日志不返回上层
- 用户可见错误与内部错误要区分

涉及接口时，重点检查：

- JSON 错误结构是否一致
- 错误信息是否足够排查
- 是否会造成前后端状态不一致

## 4. 日志

- 日志用于排查真实问题，不用于堆噪音
- 关键链路应记录必要上下文
- 避免输出敏感信息
- 临时调试日志修复后应评估是否保留

## 5. 注释

- 注释应解释“为什么”，不是重复“做了什么”
- 复杂流程、状态机分支、跨层协作点应加短注释
- 明显自解释代码不需要注释

## 6. 分层规范

### Handler

- 只处理请求解析、参数校验、响应组装、协议转换

### Service

- 只处理业务编排和领域协作

### Repository

- 只处理持久化

### pkg

- 只处理通用技术能力

## 7. 前端规范

- 复杂状态转换优先抽 helper
- 页面组件不要同时承担太多数据契约转换
- 与后端协议强相关的逻辑应集中，不要散落在多个 UI 分支里
- `Workspace` 改动要额外关注流式状态与局部 UI 状态一致性

## 8. 文档同步

以下变更默认需要回写文档：

- API 新增/修改/删除
- 架构边界变化
- 路线图阶段变化
- 新的核心约束或开发规则
