# YiStack Engineering Principles

> 本文档定义 YiStack 工程体系的最高原则。
>
> 本文档属于 YES Engineering Kernel 的 Principle Layer。
>
> 这些原则用于约束：
>
> - 人工开发
> - AI 辅助开发
> - 后续 YiStack 自身的软件工程自动化能力
>
> 当具体实现、临时需求或局部优化与本文件冲突时，应优先遵守本文件。

---

## 1. Project First

`Project` 是 YiStack 的核心业务实体。

- 需求、方案、消息、文件、运行时、预览、Git、交付都必须围绕项目组织
- 新能力设计时，先回答“它如何附着在 Project 生命周期上”
- 不允许新增脱离 `Project` 主链路的独立核心模型

## 2. Real over Mock

YiStack 优先使用真实工程能力，而不是长期依赖 mock。

- 真实文件树
- 真实 Git
- 真实运行时
- 真实预览
- 真实接口与状态流转

允许用 mock 的场景：

- 探索期原型
- 第三方依赖暂不可用
- 测试替身

但 mock 不能长期替代主链路。

## 3. Workspace is IDE

`Workspace` 是工程工作台，不是普通聊天窗口。

- 聊天只是入口之一
- 文件、预览、终端、Git、状态反馈必须服务于工程交付
- 任何交互设计都应优先保证“开发任务可控”和“状态真实可见”

## 4. AI is Engineer

AI 在 YiStack 中的角色是软件工程执行者，而不是纯问答机器人。

- AI 要对实现路径、边界、影响面、验证负责
- AI 不应只追求“能生成代码”，而应追求“能稳定交付改动”
- AI 的默认行为应是先理解上下文，再执行，而不是立即改代码

## 5. Human in Control

用户始终拥有最终决定权。

- 用户可中断、修改、拒绝、回滚 AI 的方案与实现
- 高风险改动必须允许人工确认
- AI 可以给出建议，但不能越权替用户做关键决策

## 6. MVP First

优先完成可闭环、可验证、可交付的最小能力，再扩展增强项。

- 主链路优先于附加能力
- 稳定性优先于功能数量
- 治理能力优先于表面功能堆叠

## 7. High Cohesion, Low Coupling

架构和实现必须保持高内聚、低耦合。

- 一个模块只承载一个主要变化轴
- 限制跨层直接调用
- 避免把 HTTP、业务、容器、文件、Git、持久化混进同一处

## 8. Documented before Automated

任何希望 AI 自动执行的工程能力，必须先有清晰文档化约束。

- 先定义规则，再做自动化
- 先定义流程，再做多 Agent / Skill / Engine
- 没有稳定规则的自动化，只会放大混乱

## 9. Safety before Speed

安全性和数据正确性优先于开发速度。

- 先保证权限、隔离、路径安全、状态一致性
- 不允许为了“先跑起来”长期保留明显越权或破坏性实现
- 影响容器、文件、Git、删除链路的改动必须优先考虑回退与隔离

## 10. Dogfooding

YiStack 应优先用自身工程体系来开发自身。

- 文档不是摆设，必须回流到真实开发流程
- 每次迭代都应验证 YES 是否真的约束了开发
- 如果规范无法帮助当前开发，就说明规范设计仍需迭代

## 11. Prefer Clean Target State

当前开发阶段，优先直接收敛到目标状态，而不是为了猜测中的历史兼容保留额外分支。

- 不为未被确认仍在使用的旧路径保留常量、分支或回退逻辑
- 发现默认值、策略或链路方向错误时，优先按当前最优方案直接修正
- 只有在“真实存量数据、真实调用方、真实迁移窗口”已被确认时，才允许引入兼容逻辑
- 兼容逻辑一旦存在，必须明确写出保留原因、退出条件和清理计划

## 12. Evidence before Fix

运行时问题必须先拿证据，再改逻辑。

- 先确认真实失败点，再决定修复方向
- 不能把静态阅读后的猜测当作运行时事实
- 状态码、日志、请求链路、容器输出、浏览器报错都属于有效证据
- 没有证据时，允许先加最小诊断手段，但不允许直接大改核心逻辑

## 13. Stateful Systems Need Lifecycle Design

涉及连接、会话、流式输出、终端、异步任务的能力，必须显式设计生命周期。

- 必须定义创建、运行中、异常、关闭、清理几个阶段
- 必须明确“谁负责开始、谁负责保活、谁负责清理”
- 切换 tab、切换页面、断线重连、超时清理都必须提前考虑
- 不能只让主路径可用，而忽略异常路径和恢复路径

## 14. Configuration Must Stay Consistent

默认值、配置源、种子数据、回退策略必须保持全仓一致。

- 改默认值时，必须同时检查代码常量、配置文件、初始化 SQL、migration、测试
- 不允许代码默认值与数据库种子、运行时配置长期漂移
- 不允许通过隐式 fallback 掩盖配置错误
- 若系统存在多个配置来源，必须明确哪个是最终真源
